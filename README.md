# 訪問看護Q&A（社内 Chat ボット＋クライアント向け Web アプリ）

訪問看護Q＆Aのスプレッドシートをもとに、Gemini（Google Cloud「horenso」の Vertex AI）が質問に答える仕組みです。1つの Apps Script プロジェクトで、次の2つを動かします。

| | 社内 Chat ボット | クライアント向け Web アプリ |
| --- | --- | --- |
| 使う人 | 社内スタッフ（Google Chat） | クライアント（ブラウザ・スマホ） |
| 入り方 | Chat でアプリを検索して DM | URL を開いてアクセスコードを入力 |
| 回答に使う Q&A | 全タブ・全行 | 「公開」列が○の行だけ（求職者タブは除く） |
| Gemini の呼び出し | 質問した本人の権限 | デプロイしたアカウント（雲丹亀さん）の権限 |

## ファイル構成

```
src/
  Config.gs       設定（スプシID、モデル、問い合わせ先、上限回数など）※変更はここだけ
  QA.gs           Q&A の読み込み（1時間ごと）と保存
  AI.gs           Gemini への問い合わせと回答ルール
  ChatBot.gs      社内 Google Chat ボット
  WebApp.gs       クライアント向け Web アプリ（画面から呼ばれる関数）
  Clients.gs      アクセスコードの発行・確認、1日の利用回数
  Log.gs          質問ログ
  Admin.gs        管理者用（setup、動作確認）
  Index.html      Web アプリの画面
  LogoData.html   ロゴ画像（hagukumi 看護）
  appsscript.json マニフェスト
```

## 初回セットアップ

### 1. clasp（GitHub と Apps Script をつなぐツール）を準備する

雲丹亀さんの PC で1回だけ行います。

1. [Node.js](https://nodejs.org/ja)（LTS 版）をインストールする
2. ターミナル（Windows は PowerShell）で次を実行する
   ```
   npm install -g @google/clasp
   clasp login
   ```
   ブラウザが開くので、会社のアカウント（@glug.co.jp）で許可する
3. [Apps Script の設定画面](https://script.google.com/home/usersettings) で「Google Apps Script API」を **オン** にする（オフだと clasp push が失敗する）

### 2. このリポジトリを今の Apps Script プロジェクトにつなぐ

1. このリポジトリを PC に clone する
2. Apps Script（訪問看護Q&Aボット）を開き、**プロジェクトの設定 → スクリプト ID** をコピーする
3. `.clasp.json.example` をコピーして `.clasp.json` という名前にし、`ここにスクリプトID` を書き換える
4. リポジトリのフォルダで次を実行する
   ```
   clasp push
   ```
   「Manifest file has been updated. Do you want to push and overwrite?」と聞かれたら `y`。
   **Apps Script 上のファイルは、このリポジトリの内容にすべて置き換わります**（以前の「コード.gs」は消えます）。

### 3. setup を実行する

1. Apps Script のエディタで関数 **setup** を選んで実行し、承認画面で許可する
   - 「質問ログ」タブに列（利用元・評価・ログID）が追加され、「クライアント管理」タブが作られます
   - 1時間ごとの Q&A 読み込みと、クライアント管理タブの編集トリガーが登録されます
2. **testAsk**（社内向け）と **testClientAsk**（クライアント向け）を実行し、実行ログに回答が出るか確認する
   - testClientAsk で「公開中の Q&A：0 件」と出る場合は、まだ「公開」列に○がありません（下の「スプレッドシートの準備」）

### 4. Web アプリをデプロイする

1. **デプロイ → 新しいデプロイ** → 種類の歯車で **ウェブアプリ** を選ぶ
2. 説明：`ver.5`、次のユーザーとして実行：**自分**、アクセスできるユーザー：**全員**
3. **デプロイ** を押し、表示された **ウェブアプリの URL** を控える（これをクライアントに案内する）

「全員」が選べない場合は、Workspace の管理者に、Apps Script のウェブアプリを組織外に公開できるよう設定変更を依頼してください。

### 5. 社内 Chat ボットを更新する

- Chat アプリの接続に **テスト用デプロイ（Head）** を使っている場合：clasp push の時点で反映済みです
- **バージョン固定のデプロイ** を使っている場合：**デプロイ → デプロイを管理** → 該当のデプロイを編集 → バージョン「新バージョン」→ デプロイ

Chat で「ヘルプ」と送り、「ver.5」と表示されれば更新できています。

## スプレッドシートの準備

### 「公開」列

各 Q&A タブの右端に、見出しが **公開** の列を追加します。クライアントに見せてよい行だけ **○** を入れてください（○ ◯ 〇 「公開」のどれでも可）。

- ○を付ける前に、利用者・医師・スタッフの名前を「A様」「主治医」などに置き換える
- 社内の事情や特定のステーションの経緯など、クライアントに見せたくない行には付けない
- 「求職者からのＱ＆Ａ」タブは、○があってもクライアントには使われない（`Config.gs` の `CLIENT_EXCLUDED_TABS`）

反映は1時間以内です。すぐ反映したいときは、エディタで **syncQA** を実行します。

### 「クライアント管理」タブ

| 列 | 内容 |
| --- | --- |
| クライアント名 | 入力すると、アクセスコードが自動で発行される |
| アクセスコード | 10桁の英数字（自動） |
| 状態 | 有効／停止。停止にすると1分以内に使えなくなる |
| 1日の上限回数 | 初期値 30。クライアントごとに変更できる |
| 発行日・停止日 | 自動で記入 |
| 備考 | 自由に記入 |

コードが漏れたときは、その行を「停止」にし、新しい行に同じクライアント名を入れて再発行します。

## 日常の運用

| タイミング | 担当 | やること |
| --- | --- | --- |
| クライアントの利用開始時 | 本部 | クライアント管理タブに名前を入れ、URL とコードを案内する |
| 解約・コード漏えい時 | 本部 | 状態を「停止」にする |
| Q&A の追加・修正時 | 本部 | スプシを編集し、公開してよい行に○（1時間以内に反映） |
| 週1回 | 本部 | 質問ログの「該当なし」と「役に立たなかった」を見て、Q&A を追加・修正する |
| 月1回 | 雲丹亀さん | 利用件数と horenso の費用を確認する |

## コードを変更するとき

1. `src/` のファイルを編集する
2. `git commit` → `git push`（GitHub に保存）
3. `clasp push`（Apps Script に反映）
4. Web アプリ：**デプロイ → デプロイを管理** → ウェブアプリのデプロイを編集 → 「新バージョン」→ デプロイ（URL は変わりません）
5. Chat ボット：上の「5. 社内 Chat ボットを更新する」と同じ

## 注意

- このリポジトリは **Private** にしてください
- `~/.clasprc.json`（clasp のログイン情報）は絶対にリポジトリに入れないでください
- Web アプリは雲丹亀さんのアカウントの権限で動きます。異動・退職でアカウントが止まると Web アプリも止まるため、本格運用では AI 専用アカウントへの移行を検討してください
- 費用は Gemini の利用料のみ（1回あたり約2.3円の目安）。horenso の「課金 → 予算とアラート」で月の予算を設定しておくと安心です
